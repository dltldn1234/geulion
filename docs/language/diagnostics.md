# 오류 진단

**상태: Specified** — GEULION v0.1의 source/runtime 진단 계약입니다. 진단 코드가 구현되었다는 뜻은 아닙니다.

## 진단 데이터

각 진단은 다음 정보를 가집니다.

| 필드       | 규칙                                                                                                          |
| ---------- | ------------------------------------------------------------------------------------------------------------- |
| `code`     | 아래의 안정적인 `GEdddd` 코드. 사용자 도구는 메시지 문자열 대신 이 값을 분기 기준으로 사용합니다.             |
| `phase`    | `lex`, `parse`, `resolve`, `type`, `runtime`, `internal` 중 하나                                              |
| `severity` | v0.1에서는 항상 `error`. Warning은 별도 버전에서 정의합니다.                                                  |
| `message`  | 기본 언어가 한국어인 짧은 설명. 코드 없이 메시지만으로 오류를 식별하지 않습니다.                              |
| `path`     | source/runtime 진단은 입력 파일 이름/경로. 표준 입력은 `<stdin>`입니다. internal 진단은 `null`일 수 있습니다. |
| `range`    | source/runtime 진단은 원본 소스의 시작 포함/끝 제외 범위. internal 진단은 `null`일 수 있습니다.               |
| `help`     | source/runtime 진단은 수정 제안을 항상 한 가지 포함합니다. internal 진단은 `null`일 수 있습니다.              |
| `related`  | 필요할 때 이전 선언 등 관련 위치와 설명을 담는 배열. 관련 위치가 없으면 비어 있습니다.                        |

`range`는 `{ start, end }`이며 양 끝은 `byteOffset`, `codePointOffset`, `utf16Offset`, `line`, `column`을 갖습니다. offset은 0 기반, 끝 제외입니다. line/column은 1부터 세며 UTF-16 code unit 단위입니다. 좌표는 [`lexical-structure.md`](./lexical-structure.md)의 토큰 위치 계약과 같습니다. parser가 기대 토큰 위치를 가리키면 zero-width range를 사용할 수 있습니다. runtime 오류의 range는 평가 실패를 일으킨 원본 식이어야 합니다. `related` 각 항목은 `{ message, path, range }`입니다.

진단 출력기는 다음 정보를 사람이 읽을 수 있는 형태로 렌더링합니다: 종류/코드, 메시지, 경로와 줄/열, 원본 줄과 범위 표시, 도움말, 관련 위치. 터미널의 탭 너비나 글꼴별 셀 폭은 range 계산을 바꾸지 않습니다. 컴파일러 API는 구조화된 필드를 잃지 않아야 합니다.

예시:

```text
오류 [GE2001] 이름 해석: 정의되지 않은 이름 '사용자이름'
  src/main.geul:5:4

출력(사용자이름)
   ^^^^^

도움말: 현재 범위의 변수 이름을 확인하거나 먼저 선언하세요.
```

코드는 `사용자이름` 식별자가 없는 것을 나타내며, 위치 `5:4`는 UTF-16 열 1 기반입니다. 진단 렌더러는 같은 규칙으로 source snippet과 underline을 생성합니다.

## 코드 체계

코드 번호는 범주별로 예약하며, 한 번 공개된 코드를 다른 원인에 재사용하지 않습니다.

| 범위              | 단계     | 내용                                          |
| ----------------- | -------- | --------------------------------------------- |
| `GE0000`–`GE0999` | lex      | 입력 encoding, 문자, 토큰, literal, 주석 오류 |
| `GE1000`–`GE1999` | parse    | EBNF에 맞지 않는 토큰 순서/구조               |
| `GE2000`–`GE2999` | resolve  | 이름 해석, 중복 선언, 프로그램 entry 규칙     |
| `GE3000`–`GE3999` | type     | 타입, 연산, binding, control-flow 검사        |
| `GE4000`–`GE4999` | runtime  | 잘 정의된 정적 타입 프로그램의 실행 중 실패   |
| `GE9000`–`GE9999` | internal | 컴파일러 자체 결함 또는 내부 상태 오류        |

그 밖의 번호는 미할당 예약 번호입니다. 모든 source 진단 메시지는 한국어로 작성하고, 수정 제안은 확인 가능한 규칙을 가리킵니다. 문구 개선은 같은 원인을 유지하는 한 코드 변경이 아니지만, 서로 다른 원인은 같은 코드로 합치지 않습니다.

## v0.1 진단 코드

### 어휘 분석

| 코드     | 원인                                                          | 단계 |
| -------- | ------------------------------------------------------------- | ---- |
| `GE0001` | 잘못된 UTF-8 또는 허용되지 않은 source 문자                   | lex  |
| `GE0002` | 숫자/문자열 literal 형식 또는 escape 오류, 닫히지 않은 문자열 | lex  |
| `GE0003` | 닫히지 않은 block comment                                     | lex  |

### 구문 분석

| 코드     | 원인                                                       | 단계  |
| -------- | ---------------------------------------------------------- | ----- |
| `GE1001` | 현재 위치에 올 수 없는 token 또는 필요한 token 누락        | parse |
| `GE1002` | 닫히지 않은 구분자, 불완전한 문장/표현식, 잘못된 문장 구분 | parse |

### 이름/프로그램 구조

| 코드     | 원인                                                             | 단계    |
| -------- | ---------------------------------------------------------------- | ------- |
| `GE2001` | 선언되지 않은 값/함수 이름                                       | resolve |
| `GE2002` | 같은 scope 중복 선언, 함수 중복/overload, 지역 값-함수 이름 충돌 | resolve |
| `GE2003` | `시작` 함수가 없거나 중복이거나 시그니처가 `() -> 없음`이 아님   | resolve |

### 타입과 정적 의미

| 코드     | 원인                                                            | 단계 |
| -------- | --------------------------------------------------------------- | ---- |
| `GE3001` | 요구 타입과 식/인자/반환/대입 값의 타입 불일치                  | type |
| `GE3002` | 연산자/조건/index/key의 타입 오류 또는 v0.1에 없는 함수 값 사용 | type |
| `GE3003` | `상수`에 대입 시도                                              | type |
| `GE3004` | 반복문 밖의 `중단`/`계속`                                       | type |
| `GE3005` | `없음`이 아닌 함수의 도달 가능한 경로에서 반환값 누락           | type |
| `GE3006` | `비어있음`, 빈 목록/사전 등의 타입을 정할 문맥 부족             | type |
| `GE3007` | 정수 리터럴 범위 초과 또는 실수 리터럴 binary64 overflow        | type |
| `GE3008` | 사전 literal에 중복 문자열 key                                  | type |

### 실행 중

| 코드     | 원인                                                   | 단계    |
| -------- | ------------------------------------------------------ | ------- |
| `GE4001` | checked `정수` 연산 결과가 signed 64-bit 범위를 벗어남 | runtime |
| `GE4002` | 정수 나눗셈 또는 나머지 연산의 제수가 0                | runtime |
| `GE4003` | `정수로`가 `NaN`, 무한대 또는 범위 밖 실수를 받음      | runtime |
| `GE4004` | 표준 출력에 쓸 수 없음                                 | runtime |

### 내부 오류

| 코드     | 원인                                                          | 단계     |
| -------- | ------------------------------------------------------------- | -------- |
| `GE9001` | 사용자 source 규칙 위반으로 설명할 수 없는 내부 컴파일러 실패 | internal |

메모리 고갈, 강제 종료, host process 종료는 이 진단 체계로 위장하지 않습니다. 오류가 아닌 구현/host 수준 종료입니다.

## 진단 순서와 중단

1. UTF-8 해독과 lexing은 복구 가능한 위치에서 다시 시작해 오류를 source 순서대로 수집합니다. 파일당 최대 100개의 lex 진단을 내고 나머지를 억제합니다. lex 오류가 하나라도 있으면 parse/type/code generation을 실행하지 않습니다.
2. Parser는 첫 syntax 오류에서 중단합니다. 같은 입력에 이어질 수 있는 오진을 덧붙이지 않습니다. parser 오류가 있으면 이름/타입 분석과 code generation을 실행하지 않습니다.
3. 이름 해석과 타입 검사는 가능한 독립 오류를 source 시작 위치 순으로 최대 100개 수집합니다. 한 오류에서 파생된 연쇄 오류는 억제합니다. 오류가 남으면 code generation을 하지 않습니다.
4. 진단이 100개 한도에 도달하면 마지막에 추가 오류 억제 안내 하나를 냅니다. 이 안내는 별도 GE 코드가 아닙니다.
5. runtime은 첫 runtime 오류를 보고한 뒤 즉시 현재 프로그램을 중단합니다. 오류를 예외 처리해 이어가는 기능은 v0.1에 없습니다.

## 진단 안정성

각 GE 코드는 원인 범주에 영구 할당합니다. source span, phase, code가 기계 판별 계약이고 메시지 문구는 개선될 수 있습니다. 버전 간 기존 코드를 삭제하거나 다른 원인으로 재사용하지 않습니다. 수정할 수 없는 내부 오류는 `GE9001`로 분리해 일반 source 오류처럼 표시하지 않습니다.
