# 적합성 예제

**상태: Specified** — 아래 예제는 v0.1 문법·타입·의미 규칙의 검증용 사례입니다. 예제의 compiler 구현 또는 실행 결과를 뜻하지 않습니다. 파일들은 각각 독립적인 단일 `.geul` 프로그램입니다.

## Positive: 유효 프로그램

### P-001 — 변수, 추론, 호출, 반환

```geul
함수 더하기(가: 정수, 나: 정수) -> 정수 {
    반환 가 + 나
}

함수 시작() -> 없음 {
    상수 이름: 문자열 = "시우"
    변수 점수 = 더하기(40, 55)
    만약 점수 >= 90 {
        출력(이름 + " 우수")
    } 아니면 {
        출력("보통")
    }
}
```

판정: valid. 함수 사전 선언으로 호출을 해결하고, `점수`를 `정수`로 추론합니다.

### P-002 — 반복, 대입, 중단

```geul
함수 시작() -> 없음 {
    변수 수 = 0
    동안 수 < 5 {
        출력(수)
        수 = 수 + 1
    }
}
```

판정: valid. 대입은 선언 타입을 보존하며 조건은 `불리언`입니다.

### P-003 — 컬렉션, 인덱싱, 선택값

```geul
함수 시작() -> 없음 {
    상수 수들: 목록[정수] = [1, 2, 3]
    상수 첫째: 선택[정수] = 수들[0]
    상수 이름표: 사전[문자열] = {"언어": "글리온"}
    상수 이름: 선택[문자열] = 이름표["언어"]
    출력(첫째 ?? -1)
    출력(이름 ?? "없음")
}
```

판정: valid. 목록과 사전 인덱싱은 `선택`을 반환하고 `??`의 오른쪽은 payload 타입과 같습니다.

### P-004 — 명시적 숫자 변환과 줄 연속

```geul
함수 시작()
    -> 없음
{
    상수 반올림전: 실수 = 3.5
    상수 정수값: 정수 = 정수로(반올림전)
    출력(정수값)
}
```

판정: valid. 선언 머리말의 줄 연속과 명시 변환을 사용합니다.

## Negative: 거부해야 하는 프로그램

### N-001 — 진입 함수 누락

```geul
함수 보조() -> 없음 {
    반환
}
```

판정: invalid, GE2003. `함수 시작() -> 없음`이 없습니다.

### N-002 — 타입 불일치

```geul
함수 시작() -> 없음 {
    상수 나이: 정수 = "열일곱"
}
```

판정: invalid, GE3001. 문자열을 정수에 암시적으로 대입할 수 없습니다.

### N-003 — 상수 재대입

```geul
함수 시작() -> 없음 {
    상수 횟수 = 1
    횟수 = 2
}
```

판정: invalid, GE3003. `상수` binding은 재대입할 수 없습니다.

### N-004 — 모호한 빈 목록 타입

```geul
함수 시작() -> 없음 {
    상수 항목들 = []
}
```

판정: invalid, GE3006. 빈 목록에는 기대 타입 또는 타입 주석이 필요합니다.

### N-005 — 선언되지 않은 이름

```geul
함수 시작() -> 없음 {
    출력(사용자이름)
}
```

판정: invalid, GE2001. 값 이름 `사용자이름`이 선언되지 않았습니다.

### N-006 — 비불리언 조건

```geul
함수 시작() -> 없음 {
    만약 1 {
        출력("참")
    }
}
```

판정: invalid, GE3002. 조건식은 `불리언`이어야 합니다.

### N-007 — 도달 가능한 경로의 반환 누락

```geul
함수 절댓값(값: 정수) -> 정수 {
    만약 값 >= 0 {
        반환 값
    }
}

함수 시작() -> 없음 {
    출력(절댓값(1))
}
```

판정: invalid, GE3005. 음수 입력일 때 반환값이 없는 경로가 있습니다.

### N-008 — 구문 오류

```geul
함수 시작() -> 없음 {
    상수 값: 정수 =
}
```

판정: invalid, GE1001. `=` 뒤에 표현식이 와야 하지만 `}`가 왔습니다. parser는 이 첫 예상치 못한 token에서 중단합니다.

## 적합성 분류 사용법

향후 conformance harness는 `P-*`를 accept, `N-*`를 reject해야 합니다. Negative 예제는 명시한 진단 코드를 발생시켜야 합니다. 진단 메시지의 자연어 문구는 규범 코드보다 안정성이 낮으며, 안정적인 비교는 진단 단계, 코드, source span을 기준으로 합니다. 이 문서만으로 예제를 자동 실행하는 테스트가 존재한다고 간주하지 않습니다.
