# 어휘 구조

**상태: Specified** — GEULION Language Specification v0.1의 어휘 규칙입니다. 이 문서는 토큰과 원본 위치를 정의할 뿐, Lexer 구현 상태를 뜻하지 않습니다.

## 소스 파일과 문자

- 소스는 유효한 UTF-8로 인코딩합니다. 파일 시작의 UTF-8 BOM 하나는 허용하며 토큰으로 만들지 않습니다. 파일 중간의 BOM과 잘못된 UTF-8은 어휘 오류입니다.
- 논리 줄바꿈은 LF, CRLF, CR입니다. CRLF는 한 줄바꿈으로 취급합니다.
- 바깥 공백은 ASCII space와 tab만 허용합니다. 다른 공백 문자 및 제어 문자는 문자열/주석 안이 아니면 유효하지 않습니다.
- 어휘 분석은 원본 코드 포인트 순서로 수행합니다. 토큰 간 공백은 필요할 때만 토큰 경계를 만듭니다. 연산자는 아래의 longest-match 규칙을 적용합니다.
- 오류 없는 입력의 끝에는 EOF 토큰 하나가 있습니다.

## 식별자와 Unicode

식별자 문자는 **Unicode 18.0.0**의 `XID_Start` 및 `XID_Continue` 속성을 사용합니다. 첫 문자는 `XID_Start` 또는 `_`, 나머지는 `XID_Continue` 또는 `_`여야 합니다. 그 집합에서 `Default_Ignorable_Code_Point`와 bidi 제어 문자를 제외합니다. 따라서 한글, 한자, 라틴 문자 및 그 속성에 포함된 문자 조합을 사용할 수 있고 숫자는 첫 글자가 될 수 없습니다. `$`, 공백, emoji는 허용하지 않습니다.

구현은 UAX #31의 XID 식별자 정의를 기준으로 Unicode 18.0.0 데이터에 고정해야 합니다. 위 제외 집합을 적용한 프로파일을 사용합니다. 런타임이 제공하는 다른 Unicode 버전의 문자 속성으로 허용 범위를 넓히거나 줄여서는 안 됩니다. ([UAX #31](https://www.unicode.org/reports/tr31/))

식별자를 이름으로 비교하기 전에 **NFC**로 정규화합니다. 예약어 검사도 NFC 결과에 적용합니다. 따라서 정규 조합상 같은 식별자는 같은 이름이고, 분해 표기된 예약어도 예약어와 충돌합니다. 원본 철자는 진단·표시에 보존합니다. NFKC 호환 정규화는 적용하지 않습니다. ([UAX #15](https://www.unicode.org/reports/tr15/))

시각적으로 닮은 서로 다른 코드 포인트는 별도 식별자입니다. v0.1은 혼합 스크립트나 Unicode confusable을 오류로 금지하지 않습니다. 진단 또는 편집기 경고는 향후 제안입니다. 예약어는 식별자로 사용할 수 없고 prelude 함수 이름은 다시 선언할 수 없습니다. 지역 값 이름이 함수/prelude 이름과 충돌하는 규칙은 `semantics.md`에 따릅니다.

`시작`은 어휘 예약어가 아닙니다. 프로그램 검증 단계에서 유일한 진입 함수 이름으로 검사합니다. `출력`, `정수로`, `실수로`는 prelude 이름이며 일반 식별자 토큰으로 lexing한 뒤 이름 해석으로 확인합니다.

## 예약어

다음 낱말은 NFC 정규화 후 예약 토큰으로 분류하며 식별자로 쓸 수 없습니다.

| 범주             | 예약어                                     |
| ---------------- | ------------------------------------------ |
| 선언/함수        | `상수`, `변수`, `함수`, `반환`             |
| 제어 흐름        | `만약`, `아니면`, `동안`, `중단`, `계속`   |
| 논리/불리언      | `그리고`, `또는`, `아니다`, `참`, `거짓`   |
| 기본 타입/값     | `정수`, `실수`, `문자열`, `불리언`, `없음` |
| 컬렉션/선택 타입 | `목록`, `사전`, `선택`, `일부`, `비어있음` |

키워드는 대소문자 변형, 동의어, 조사 접미 형태를 허용하지 않습니다. ASCII 대소문자는 서로 구별되며, 예약어 자체는 위에 적힌 NFC 문자열만 인식합니다.

## 줄바꿈과 문장 구분

`NEWLINE`은 LF/CRLF/CR을 나타내는 어휘 토큰입니다. 블록 주석 안의 줄바꿈도 토큰 스트림에서 보존합니다. 프로그램 본문과 블록에서 `NEWLINE` 또는 `;`가 문장 구분자입니다. 같은 줄에서 둘 이상의 문장을 쓸 때는 `;`가 필요합니다. 블록의 마지막 문장 앞 구분자는 생략할 수 있습니다.

다음 경우 줄바꿈은 구분자가 아니라 공백입니다.

1. 괄호 `(...)`, 대괄호 `[...]`, 사전 리터럴 `{...}` 안.
2. 줄의 마지막 유효 토큰이 `=`, `:`, `,`, `->`, `만약`, `동안` 또는 단항/이항 연산자일 때. 다음 줄은 그 구문을 이어야 합니다.
3. 함수 머리말의 매개변수 `)` 뒤에 반환형 화살표 `->`가 다음 줄에 올 때.
4. 함수·조건·반복 머리말이 끝나고 본문 `{`가 다음 줄에 올 때.
5. `만약` 본문 뒤에 `아니면`이 다음 줄에 오거나, `아니면` 뒤에 `만약` 또는 `{`가 다음 줄에 올 때.

그 밖의 줄바꿈은 문장을 끝냅니다. 따라서 완성된 식 다음 줄의 `+`는 앞 식을 이어가지 않습니다. `반환` 뒤 줄바꿈은 반환문을 끝내며 다음 줄 식을 반환값으로 묶지 않습니다. 블록 `{...}` 내부의 줄바꿈은 구분자이고, 사전 리터럴 `{...}` 내부의 줄바꿈은 항목 사이에 놓일 수 있는 공백입니다. 사전 항목 사이에는 항상 쉼표가 필요합니다.

## 주석

- `//`는 다음 LF/CRLF/CR 직전까지 한 줄 주석입니다. 줄바꿈은 주석에 포함되지 않고 `NEWLINE`으로 남습니다.
- `/*`와 첫 번째 뒤따르는 `*/` 사이가 블록 주석입니다. 블록 주석은 중첩되지 않습니다. 내부의 줄바꿈은 각각 `NEWLINE`으로 남습니다.
- 닫히지 않은 블록 주석은 `GE0003`입니다. 문자열 안의 `//`, `/*`, `*/`는 일반 문자입니다.

## 리터럴

### 정수와 실수

- 정수 리터럴은 ASCII 10진 숫자 하나 이상입니다. 앞자리 0도 10진수로 해석하며 8진수/16진수 접두사와 숫자 구분자 `_`는 없습니다.
- 실수 리터럴은 `숫자.숫자` 또는 `숫자` 뒤 지수부(`e`/`E`, 선택 부호, 숫자) 형식입니다. 소수점 앞뒤에 숫자가 모두 필요합니다. `1.`, `.5`는 리터럴이 아닙니다.
- 부호는 리터럴 일부가 아니라 단항 `+`/`-` 연산자입니다. `NaN`과 무한대는 표기 리터럴이 아닙니다.
- 유효한 숫자 뒤에 식별자 시작 문자가 바로 붙으면 두 토큰으로 나누지 않고 잘못된 숫자 토큰으로 진단합니다.

### 문자열

문자열은 큰따옴표 `"..."`로 감쌉니다. 실제 줄바꿈과 원시 C0 제어 문자는 허용하지 않습니다. 지원 escape는 `\\`, `\"`, `\n`, `\r`, `\t`, `\0`, `\u{H...}`입니다. Unicode escape에는 1~6개의 16진 숫자가 필요하고 Unicode scalar value 범위(U+0000..U+10FFFF, surrogate 제외)만 허용합니다. 잘못된 escape는 `GE0002`입니다.

문자열은 유효한 Unicode scalar value의 순서열입니다. 문자열 값에는 정규화를 적용하지 않으며 보이는 글자가 정규 조합상 같더라도 코드 포인트가 다르면 다른 문자열입니다. 문자열 보간, 작은따옴표, 여러 줄 문자열은 v0.1에서 지원하지 않습니다.

### 불리언, 없음, 선택

- `참`, `거짓`은 불리언 리터럴입니다.
- `없음`은 Unit 값입니다.
- `비어있음`은 `선택[T]` 문맥이 있어야 타입을 결정할 수 있는 선택 타입의 빈 값입니다.
- `일부(식)`는 식의 타입을 담은 `선택[T]` 값을 만듭니다.

### 컬렉션

- 목록 리터럴은 `[식, ...]`이며 빈 목록 `[]`를 허용합니다.
- 사전 리터럴은 `{"문자열 키": 값, ...}`이며 빈 사전 `{}`를 허용합니다. 키는 문자열 리터럴만 허용합니다.
- 쉼표로 나열할 때 마지막 항목 뒤 쉼표는 허용합니다. 목록 항목, 호출 인자, 함수 매개변수, 사전 항목 사이에는 쉼표가 필수이며 줄바꿈만으로 항목을 나누지 않습니다. 문자열 값은 정규화하지 않으므로 같은 리터럴 안에서 코드 포인트 순서가 같은 사전 키가 두 번 나오면 의미 분석 오류입니다.

## 기호 토큰

다중 문자 토큰은 한 문자 토큰보다 먼저 longest-match로 인식합니다.

| 토큰        | 표기                                        |
| ----------- | ------------------------------------------- |
| 화살표      | `->`                                        |
| 동등/비동등 | `==`, `!=`                                  |
| 순서 비교   | `<=`, `>=`, `<`, `>`                        |
| 선택 합치기 | `??`                                        |
| 대입/산술   | `=`, `+`, `-`, `*`, `/`, `%`                |
| 구분/그룹화 | `(`, `)`, `[`, `]`, `{`, `}`, `:`, `,`, `;` |

`>=`는 항상 단일 비교 토큰이고 `>>`, `<<`, 증감 연산자 및 복합 대입 토큰은 v0.1에 없습니다. 타입 매개변수 표기는 `<...>`가 아니라 대괄호 `목록[정수]`를 사용하므로 비교 연산자와 generic 닫는 괄호를 분할할 필요가 없습니다.

## EBNF terminal class

`grammar.ebnf`가 사용하는 lexical terminal은 다음과 같습니다.

```text
DIGIT      = ASCII "0".."9"
IDENTIFIER = (XID_Start | "_") (XID_Continue | "_")*
INTEGER    = DIGIT+
REAL       = DIGIT+ "." DIGIT+ EXPONENT?
           | DIGIT+ EXPONENT
EXPONENT   = ("e" | "E") ("+" | "-")? DIGIT+
NEWLINE    = CRLF | CR | LF
EOF        = source 끝
```

`IDENTIFIER` production에도 `Default_Ignorable_Code_Point`와 bidi 제어 문자 제외를 적용합니다. NFC 정규화 후 예약어와 일치한 철자는 `IDENTIFIER`가 아니라 해당 키워드 토큰입니다. `STRING`은 큰따옴표로 둘러싼 유효한 scalar/escape 순서입니다. `IDENTIFIER`는 원본 철자와 NFC 정규화된 이름을 함께 보존합니다. `INTEGER`, `REAL`, `STRING`에는 sign이 포함되지 않습니다. 어휘 분석기는 숫자로 시작하는 연속 문자열을 숫자 후보 전체로 검사합니다. 유효한 숫자 후보 뒤에 식별자 continue 문자가 바로 붙거나 소수점 뒤 fractional digit가 없으면 두 토큰으로 쪼개지 않고 `GE0002`를 냅니다. 예를 들어 `12이름`, `1e`, `1.`은 잘못된 숫자입니다. `.5`는 숫자 토큰이 아니며 `.` 위치에서 `GE0001`입니다.

키워드 토큰은 완전한 `IDENTIFIER`를 NFC 정규화한 결과가 예약어 표와 정확히 일치할 때만 만들어집니다. 식별자 접두사가 키워드와 같아도 나머지 문자가 유효하면 하나의 `IDENTIFIER`입니다. 연산자/주석 delimiter는 위 표에 열거된 토큰만 인정합니다.

## 토큰 위치 계약

각 토큰은 원본 UTF-8 파일을 기준으로 다음의 0 기반, 끝 제외 시작/끝 offset을 보존합니다.

- UTF-8 byte offset: 파일 저장 위치 및 원본 바이트 슬라이스
- Unicode code point offset: 언어 텍스트의 scalar 순서
- UTF-16 code unit offset: JavaScript 및 편집기 프로토콜 연결

초기 BOM은 토큰과 열 계산에서 제외합니다. byte offset은 파일의 실제 바이트 기준이므로 BOM 뒤의 첫 토큰은 byte offset 3에서 시작합니다. code point 및 UTF-16 offset은 BOM을 제외한 텍스트 기준입니다.

오류 위치의 줄/열은 1부터 세고, 열 단위는 UTF-16 code unit입니다. 탭은 열 하나로 계산하고 화면 표시 폭은 고려하지 않습니다. 줄바꿈은 다음 줄 열 1을 시작합니다. 보조 평면 문자는 UTF-16 열 두 칸입니다. grapheme cluster 너비나 화면 표시 폭은 진단 위치의 기준이 아닙니다. LSP 3.17의 UTF-16 position을 쓰는 클라이언트와 연결할 때 진단 열에서 1을 빼고, 다른 encoding 협상이 있으면 그 인코딩으로 변환합니다. ([LSP 3.17 Position](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/#position)) 원본 진단 범위는 NFC 정규화 전 코드 단위/바이트 offset을 가리킵니다.

## 어휘 오류 코드

- `GE0001`: 잘못된 UTF-8 또는 허용되지 않은 문자
- `GE0002`: 잘못된 숫자/문자열 리터럴 또는 escape
- `GE0003`: 닫히지 않은 블록 주석

오류 코드와 공통 진단 형식의 규범 정의는 `diagnostics.md`에 있습니다.
